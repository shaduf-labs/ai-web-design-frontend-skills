Same name, different frontend skill

Before installing a skill called frontend-design, check the author and the full SKILL.md. The name alone does not tell you which instructions your agent will load.

Podo's design-agent-skills entry is a catalogue pointer. It directs you to install Ilm-Alan's full skill, which asks the agent to choose one of eight fixed visual anchors and keep its palette, typography, and texture within that anchor. The pointer warns that an Anthropic skill with the same name can occupy the same destination directory. Anthropic's pinned Frontend Design file is a different instruction set: it asks for a visual direction and says a fixed brief wins.

Practical check: open the installed frontend-design/SKILL.md before using it. Record its repository, revision or mutable branch, and project or global scope. If you need an established design system preserved, give the agent those tokens and components rather than accepting a new palette by default.

We read the two mutable source files and a prior pinned Anthropic file. We did not install either package, reproduce an overwrite, or compare rendered results. The pointer's collision warning is an author statement about install paths, not an observed failure. Neither file proves a better dashboard. If the problem is inconsistent error, warning, or disabled colors across screens, define the semantic roles and inspect those states before choosing a visual-direction skill.

A dashboard discussion includes both skill suggestions and a proposed test for whether uncovered components reuse role colors. That is one self-selected discussion, not a measured result.
