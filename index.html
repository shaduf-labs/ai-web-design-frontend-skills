Initial catalogue · checked 14 September 2026

Three skills for three different frontend jobs.

Use a visual-direction skill before a new surface, a UI-review skill before shipping, and a React/Next performance skill when the interface is already real enough to get slow. None of them proves the result is good. You still need your design system, a browser check, and judgment.

Fast decision: building a new landing page or dashboard? Start with Frontend Design. Reviewing an existing UI? Start with Web Design Guidelines. Fixing React or Next.js performance? Use Vercel React Best Practices.

Start here

Strong fit

Frontend Design

Use this for a new page, dashboard, or substantial visual refresh when the brief needs an intentional direction before code.

Needs
A concrete audience, product job, and constraints. A screenshot loop if your environment supports one.
Watch for
It is a creative instruction set, not your product strategy or existing design system. We read it; we did not test it.
Source
Anthropic skills, commit 41bbe19 · Apache-2.0 folder licence · substantive update 3 September 2026.
Conditional fit

Web Design Guidelines

Use this after implementation to ask an agent for a terse UI review with file-and-line findings.

Needs
The files to review and network access to retrieve Vercel's current guideline set.
Watch for
Its package is pinned here, but its rules are fetched fresh. Record which rules were used; a clean output is not an accessibility test.
Source
Vercel Agent Skills 063bee94 · skill metadata 1.0.0 · MIT collection.
Conditional fit

Vercel React Best Practices

Use this for React or Next.js pages when bundle size, waterfalls, rendering, or re-renders are part of the job.

Needs
A React or Next.js codebase. It is not a general visual-design skill.
Watch for
The source also points to a full compiled guide. Prefer the relevant rules first; we have not measured its context cost in any agent.
Source
Vercel Agent Skills 063bee94 · skill metadata 1.0.0 · MIT.

A skill is not a visual acceptance loop

WhenDo thisWhat counts as evidence
Before codeName the component boundary, existing tokens, and the states that matter.A brief a teammate can challenge.
During buildMake one surface change at a time. Reuse existing components before creating a parallel system.A focused diff and the intended states.
Before mergeRender desktop and mobile states. Check empty, loading, error, and long-text paths.Screenshots and browser checks—not a confident prompt response.

This workflow is a pool recommendation informed by current community discussion, not a controlled skill comparison.

Install without guessing

The open skills CLI documents project and global scopes and lists Codex as a target. For a Vercel skill, inspect the exact source first, then use its documented command, for example npx skills add https://github.com/vercel-labs/agent-skills --skill web-design-guidelines. Do not let a directory listing or install count decide whether a skill belongs in your repository.
