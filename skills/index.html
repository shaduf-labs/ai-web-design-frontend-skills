Catalogue snapshot · 3 October 2026

Compare skills by task and requirements.

Eleven listings are source-pinned; five current sources are mutable. This is not a ranking. “Strong fit” means task fit in the stated conditions, not a measured better outcome. Anthropic Frontend Design assumes freedom to choose a palette and type; preserve your existing design system when that freedom is not available. An external functional benchmark found mixed results from injected web skills; it did not test these listings. See the baseline comparison limit.

Existing design system: Start with a brief that names the real components, tokens, route, and states. Vercel Labs DS Skills Pipeline generates a project-specific skill from source; it is not a seventeenth ready-made listing. The author marks Codex support expected, and we have not tested its result. See when to build one.

Discovery hold: The OpenDesign frontend-skill entry points to an upstream skill that OpenAI removed. It is not a full workflow; check any actual instruction file before use. We did not install it.

Package hold: Snowe UI Skill is not listed. GitHub currently reports a YAML error in its SKILL.md frontmatter. We did not test host behavior. Check that metadata parses before you compare a method.

Game UI is a separate lane

Look elsewhere: Game UI Frontend is for a browser-game playfield, not an ordinary product dashboard. If the player can move or aim, record the camera and input state beside the HUD state; the screen can fail even when the overlay looks polished.

One record every installation should add

Adoption record: target agent · project or global scope · upstream URL and revision · local edits · update review. For a single-direction rendered loop, add the route, system constraints, one chosen direction, required states and widths, local checks, and retained render evidence. For a visual-direction selection loop, add the minimum brief, references, three directions, and selected target. For a design-and-build skill, add user and screen job, existing system, in-scope states, viewports, and input methods. For a project-bound feedback loop, add the represented route, source tokens, human decisions, annotations, export, applied diff, and later live-route comparison. Add the proof resource too: a concept and browser comparison for a visual build; a named route, interaction, expected result, Browser path, backend, viewport, and session context for targeted QA; a named journey and accepted screenshots for a flow audit; a target URL, named session, output directory, retries, and retained repro artifacts for exploratory QA; or the relevant files and rule revision for a code review.

Not in this catalogue

Prompt collections, component libraries, templates, whole applications, and design-system conversion pipelines solve different problems. A repository with a SKILL.md can also bundle scripts and references, so inspect every file before adoption.
